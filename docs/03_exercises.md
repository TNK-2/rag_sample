# 演習

簡単なものから順に並べています。各演習のあと `python evaluate.py` で数字がどう変わるかを見るのがおすすめです。

## 演習 1: パラメータを動かす
`python main.py "..." --retrieve-only --chunk-size 100 --top-k 5` のように値を変えて、
検索結果とプロンプトがどう変わるか観察しましょう。`python evaluate.py --sweep` の結果とも照らし合わせてください。

## 演習 2: 資料を追加する
`data/` に新しい Markdown (例: `05_benefits.md` 福利厚生) を追加し、その内容を質問してみましょう。
コードは一切変えずに、LLM が新しい知識で答えられるようになるはずです。これが RAG の一番の強みです。

## 演習 3: 資料に答えがない質問をする
`python main.py "社員食堂のメニューは？"` のように、資料に書かれていないことを聞いてみましょう。
「分かりませんでした」と答えられるか確認し、`rag/generator.py` の `SYSTEM_PROMPT` を変えると挙動がどう変わるか試してください。

## 演習 4: 失敗している質問を直す
`evaluate.py` の「本を買うのに会社はいくらまで出してくれる？」は TF-IDF では見つかりません
(資料では「書籍購入」と書かれているため)。次のどれかで直してみましょう。

- **ニューラル埋め込み**: `pip install sentence-transformers` して `python evaluate.py --embedder neural`
- **クエリ書き換え**: 検索前に LLM に質問を言い換えさせる (「本を買う」→「書籍 購入」)。
  `RAGPipeline.retrieve` の中で Claude を 1 回呼ぶ形で実装できます
- **ハイブリッド検索**: TF-IDF とニューラルのスコアを重み付きで足し合わせる

## 演習 5: overlap を文の境界で取る
今の `split_text` は、直前チャンクの末尾をぴったり `overlap` 文字で切って重ねるため、
「従事してください。」のように文の途中から始まるチャンクができます。
文の境界 (「。」の後) から重ねるように改良してみましょう。`tests/test_rag.py` のテストも更新してください。

## 演習 6: 差分だけ再インデックスする
今は `python ingest.py` でコレクションを丸ごと作り直しています。
ファイルごとにハッシュ値を payload に保存しておき、変更されたファイルのチャンクだけ
削除 → 追加するようにしてみましょう (Qdrant の `delete` に `Filter` を渡すと、条件に合うポイントをまとめて消せます)。
TF-IDF の場合は IDF がコーパス全体に依存するため、厳密には全部作り直しが必要になる点にも注目してください。

## 演習 6.5: Qdrant をサーバーモードで動かす
Docker で Qdrant を起動し (`docker run -p 6333:6333 qdrant/qdrant`)、`QDRANT_URL=http://localhost:6333` を設定して
`python ingest.py` を実行してみましょう。http://localhost:6333/dashboard でコレクションの中身 (ベクトルと payload) を覗けます。
組み込みモードでは同時に開けなかった `main.py` と `api.py` を、同時に動かせるようになるはずです。

## 演習 7: 評価セットを増やす
`evaluate.py` の `EVAL_SET` に、自分で考えた質問を 10 個追加しましょう。
特に「資料と違う言葉で聞く質問」を増やすと、各方式の強み・弱みがはっきり見えてきます。
